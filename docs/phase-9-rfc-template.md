# Phase 9 — RFC Proposal Template

This template is the canonical format for protocol extension, schema change, and ecosystem policy proposals in Concordance.
It is intended for contributors, reviewers, and governance participants to make proposals comparable, traceable, and reviewable.

## RFC Metadata

- Title:
- Author(s):
- Date:
- Status: Draft / Under Review / Approved / Rejected / Superseded
- Related Phase: Phase 9
- Issue/PR:
- Reviewers:

## Summary

Explain the problem the proposal solves and the intended outcome in 2-3 sentences.

## Motivation

- Why is this change needed?
- What real problem or gap does it address?
- Who benefits from the change?
- What happens if this is not adopted?

## Scope

- What is included in this proposal?
- What is explicitly out of scope?
- Are there any backwards-compatibility constraints?

## Specification

- Protocol or schema changes
- New message formats, fields, record types, or registry behaviors
- Required validation rules, semantics, and expected processing flows
- Examples of the new or changed payloads

## Compatibility and Interoperability

- Protocol compatibility guarantees
- Required version upgrades for adapters, registries, and clients
- Migration guidance for adopters
- Dependency on other RFCs or standards

## Security Considerations

- What are the security impacts of this change?
- Does it introduce new attacker surfaces or trust assumptions?
- How should implementation and deployment mitigate those risks?

## Governance Impact

- Does this change require new governance primitives, policy definitions, or registry roles?
- Does it affect adapter approval, certification, or revocation semantics?
- Does it require updates to the security disclosure process or release cadence?

## Implementation Plan

- Proposed implementation phases or milestones
- Test coverage and interoperability benchmarks
- Required documentation and registry metadata updates
- Validation criteria for acceptance

## Adoption Checklist

- [ ] Independent implementation(s) exist or are planned
- [ ] Conformance tests are available
- [ ] Security review completed
- [ ] Registry publication rules are updated
- [ ] Governance review and approval recorded

## Alternatives Considered

- Alternative approaches that were evaluated
- Reasons they were rejected or deferred

## References

- Related RFCs, docs, protocols, or standards
- Issue links, design notes, and reference implementations

## Notes

Additional context, open questions, or future work.
